## 二、归档正确性（名称归一化）

### #8 繁体文件名必须先转简体再检索 Bangumi

- **现象**：繁体标题检索命中的是**错误条目**，而不是「搜不到」——
  `孤獨搖滾` → 首条是「透明的孤独」；`咒術迴戰` → 首条是 4D 电影版；`佐賀偶像是傳奇 捲土重來` → 首条是第一季。
- **原因**：旧的手写「繁→简高频字表」缺了几百个常用字（給 僅 擇 擊 捲 搖 換 檔 剋 傳 迴 獨 滅 細 …）。
- **做法**：换成 OpenCC `TSCharacters.txt` 生成的完整字表（2966 条单字映射，内嵌数据，**保持零运行时依赖**）；
  判据「**含假名 ⇒ 日文原名原文优先；不含假名 ⇒ 简体优先**」（不能无脑转，`進撃の巨人`→`进击の巨人` 反而更差）。
  ⚠️ 换字表会改变 `aliasKey()` ⇒ 缓存键 / 别名表键全变，换之前要确认用户的方案记忆是空的或先做键迁移。
- **验证**：自检 **A19**（7 条繁体标题全对）。

### #9 罗马音要靠网页检索还原，不能靠相似度

- **现象**：罗马音 / 英文标题大量停在「待确认」，`Full Dive` 这类甚至会被不相干的名字抢走。
- **原因**：罗马音 ↔ 中文译名之间**没有字符串相似度可言**；而纯靠 Bangumi 检索首条又不稳。
- **做法**：新增 **L2b 前置网页检索**（Wikipedia → Kitsu → AniList → Jikan 并行竞速，9s 预算，
  可选 Google CSE），拿到日文原名后再回查 Bangumi；结果缓存 30 天。
  同时新增 **文件修改时间加权**（首播晚于文件时间 −0.30；同季 +0.14）作为旁证。
  ⚠️ 绝不能「谁先返回用谁」：Kitsu/Jikan 是子串匹配，`5Hanayome` 会匹配到 `瀬戸の花嫁`。
  ⚠️ 续作不能写裸标题别名（`Yuru Camp` 写进第二季 ⇒ 第一季文件下次归错）。
- **验证**：自检 A14–A18；分组结果与改造前逐条对比一致（743/743）。

## 三、文件与目录操作安全

### #10 🔴 UNC 前缀被压掉，1076 个文件 / 387 GB 被搬到本机磁盘

- **现象**：归档目标静默变成本机磁盘路径 `<盘符>:\NAS\…`，NAS 上的文件被「移走」。
- **原因**：`parts.join('\\').replace(/\\+/g,'\\')` 把 `\\NAS\share\…` 压成 `\NAS\share\…`，
  Windows 把单个前导 `\` 解析为「当前盘符根目录」。
- **做法**：① 统一 `fsx.joinWinPath()`（先取出开头 `\\` 再压中间重复斜杠，前后端同一套实现）；
  ② 执行前校验目标必须在归档根内，否则拒绝该条目；
  ③ e2e 补 UNC 纯字符串断言（A21/A22）—— 因为**原来的 e2e 全用本地临时目录，正好绕过了这个 bug**。
- **善后**：527 项 / 195.74 GB 全部搬回，**成功 527 / 失败 0**（≈170 MB/s）；
  命名冲突 3 组走 `(1)` —— MD5 实测同组内容不同 ⇒ **必须都保留**，不能按文件名去重；
  本机残留副本删净，空目录逐级删除。
- **验证**：A21/A22；UNC 完整性审计（对 `data/` 下文件统计 `\\+NAS` 的前导反斜杠个数：4=正常，2=已损坏）。

### #11 其它安全项

- 冲突处理只剩「自动重命名 `(1)`」与「跳过」，**无覆盖**；`unrecognized` / `deferred` 默认不移动。
- 目标越界拒绝执行且源文件不动（A23）。
- **断点续跑**：源已不在且目标已存在 ⇒ 计「跳过」并**不写日志**（写了会让撤回多动一次文件）。
- 空目录清理只向上走、遇非空或权限失败立即停、**绝不删归档根**（A34/A35 锁边界）。
- 端口被占用自动 +1 并写回配置；关闭走 `POST /api/shutdown`（优雅落盘）而非强杀，
  否则 Windows 的 TIME_WAIT 会让下次启动端口漂移到 10000。

## 四、媒体库与二次整理

### #12 三种「归错了」都能就地改（含整目录）

- **现象**：归档结果发现归错，只能撤回再归档；独立子目录（整包归档进来的文件夹）没法整体处理。
- **做法**：`EntryMoveHost` 统一入口，按「文件是否已在磁盘上」分流：
  计划里的 → 改方案记忆；已在磁盘的 → `/api/library/move` 真实移动（单文件 / 整目录 / 整批）。
  子目录在磁盘上是真实文件夹 ⇒ 支持**整体移动 / 整体撤回**（`LibrarySubDir` 增加
  `fullPath`/`originPath`/`revertable`/`totalSize`）。
  ⚠️ `revertable` 不能靠「里面有文件就能撤」推：`SP` / `OP&ED` 是归档时新建的子目录，本身没有移动日志。
- **验证**：A30/A31/A36（库内移动 / 批量移动 / 整目录移动）。

### #13 资源管理器打开（两个静默失败）

- **现象**：点「打开文件夹」什么都不发生；或打开了「文档」。
- **原因**：① `windowsHide: true` 会让 GUI 窗口**被创建但隐藏**（命令成功、`spawn` 触发、API 返回 ok，屏幕上什么都没有）；
  ② `explorer /select,"<路径>"` 的引号**只能包住路径**，而 Node `spawn` 默认正好是错的那种写法。
- **做法**：直接 spawn GUI 程序时 `windowsHide: false`；`windowsVerbatimArguments: true` + 手动拼 `"/select,<path>"`。
- **验证**：A32（坏路径拒绝）/ A33（引号写法）；GUI 类验证手法＝数 `MainWindowTitle`（隐藏窗口不计数）。

### #14 「秒开」：扫描结果存快照，不必每次重扫

- **做法**：扫描成功存快照（服务端 `data/last-scan.json` 权威 + 浏览器 localStorage 本机备份）；
  只存 groups **不存 plan**（载入后重算目标路径与冲突）；执行归档后**剪裁**快照、撤回后只标「建议重扫」。
  ⚠️ 必须校验 `sourceRoot/targetRoot` 一致才套用。
- **验证**：A25/A26 系列 + 手工验证「先开页面再启服务」也能拿到快照。

## 五、可靠性、反馈与性能

### #15 停止 / 继续与失败重试

- **停止 / 继续**：进度条 + 当前文件 + 百分比 + 「⏹ 停止归档」；停止后黄条给「继续归档」「撤销整批」，
  失败项红色提示条可展开看路径与原因（A25–A28）。
- **失败自动重试**：与 #3 配套；唯一名只算一次并复用（否则「已复制成功但删源失败」会生成 `(2)` 副本）。

### #16 列表性能：折叠必须「不渲染」

- 8286 个文件行曾建 **53,782** 个节点；改成 `{!collapsed && …}` 后降到 **7,809**；
  卡片与条目分批（先 40 条 + 「显示全部」）。

### #18 通用教训

① 别在热路径上调 `preprocess`/`aliasKey`（单次约 40µs）；
② 别每次操作都整文件重写 JSON（缓存常驻内存 + 合并延迟写盘）；
③ NAS 上提速靠**有界并发**，不是多线程。
