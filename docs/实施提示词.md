## 1. 项目一句话

扫描 NAS 上「已看/Anime」**以外**的所有视频文件与文件夹 → 识别同一部番剧 → 把名称归一化为**官方中文名** → 按**首播年份/月份**剪切到 `已看/Anime/{年份}/{月份}/{官方中文名}/`；并对归档结果建立本地索引，提供一个**可随时打开的离线网站**用于浏览、检索、图表、播放与撤回。

## 3. 已确认决策速查（**禁止再询问，直接实施**）

### 3.1 归档规则

| 项 | 决策 |
| --- | --- |
| 归档根目录 | NAS 的 `已看/Anime`，**路径由界面输入**，不写死；不处理账号密码 |
| 扫描范围 | NAS 共享根目录，**排除归档根目录及其所有子目录** |
| 目录结构 | `{首播年份}/{月份两位}/{官方中文名}/` |
| 子目录 | `SP/`（SP/OVA）、`OP&ED/`（OP/ED/NC） |
| 特殊目录 | `_未识别/`、`_待确认/` 放在**归档根目录内** |
| 多季/续作 | **各自独立文件夹**，按各自首播年月划分 |
| 同名不同作品 | **强制人工确认**，不自动归组 |

### 3.2 命名归一化

| 项 | 决策 |
| --- | --- |
| 权威数据源 | **Bangumi** |
| 兜底顺序 | 官方中文名 → 通用译名 → **日文原名**；❌ **不使用罗马音** |
| 置信度阈值 | **0.70**（≥0.90 自动 / 0.70~0.90 需确认 / <0.70 不移动） |
| 别名表 | `aliases.json`，人工确认结果**写回** |
| 联网 | **需要**，仅用于查 Bangumi；结果缓存，断网降级 |

### 3.3 文件操作

| 项 | 决策 |
| --- | --- |
| 移动方式 | **剪切**；源与目标均在 NAS → 直接 Move |
| 自动重命名 | ❌ **不做**（文件名永不改动） |
| 手动重命名 | ✅ **仅限番剧文件夹名**（归档结果区改方案 / 媒体库真实改名） |
| `年份/月份` 层级 | ❌ 不可改 |
| 冲突 | **自动加 `(1)`** 或 **跳过**；❌ **无「覆盖」选项** |
| 同集多版本 | **全部保留** |
| 撤回 | ✅ 整批撤销 + ✅ 单文件撤回 |
| 安全 | 默认 dry-run、全量日志、失败不删源 |

### 3.4 媒体库与运行形态

| 项 | 决策 |
| --- | --- |
| 形态 | **静态网站 + 本地轻量 Node 服务**（方案 B） |
| 端口 | **`9999`**（被占用时自动 +1 并写回配置） |
| 启停 | ✅ 一键启动（桌面快捷方式）/ 一键关闭（网页「⏻ 关闭服务」按钮） |
| 开机自启 | ❌ 不需要 |
| 索引文件 | `library.json` 存**网站目录** |
| 索引重建 | 归档完成后**自动重建** |
| 时长 | ❌ **不显示**（不装 ffprobe） |
| 封面 | ❌ **不使用** |
| 播放 | 由**本地服务**调起 Windows 默认播放器 |
| 检索 | **仅媒体库**；不需要按字幕组/分辨率/大小/状态检索 |
| 图表 | ✅ 各年份番剧数量 + 各年份占用空间 |
| 特殊目录 | `_未识别/`、`_待确认/` **纳入索引**，灰色分组展示，**不参与图表统计** |
| 主题 | **跟随系统**（`prefers-color-scheme`） |
| 平台 | **仅 Windows** |
| 规模 | 单次 < 1000 文件 |
| 目录监控 | ❌ 不实现，**手动触发** |

## 6. 硬性约束

### ✅ 必须做（DO）

1. **默认 Dry-Run**：先出方案，用户确认后才动文件
2. **每一次文件操作都写日志**（原路径 → 新路径 + 时间戳 + 结果），可反向执行
3. **扫描时严格排除归档根目录**（用绝对路径归一化后判断，不要用字符串前缀粗暴比较）
4. **路径安全**：拼接目标路径前校验非法字符与 Windows 260 限制
5. **失败隔离**：单条失败不中断整批，失败项保留源文件
6. **服务未启动时网站仍可只读浏览**（读 `library.json`）
7. **界面与 `demo/index.html` 保持一致**（两视图、状态色、弹窗样式）

### ❌ 禁止做（DON'T）

1. ❌ **不得删除用户任何文件**（除「跨设备剪切」语义中校验通过后删除源）
2. ❌ 不提供「覆盖」冲突选项
3. ❌ 不自动重命名文件（文件名永不改动）
4. ❌ 不允许修改文件名或 `年份/月份` 层级
5. ❌ 不引入 ffprobe / 封面下载
6. ❌ 不做目录监控 / 常驻后台
7. ❌ 不检索待归档区域（检索只作用于媒体库）
8. ❌ 不要自己发明需求；文档没写的先问

## 7. 领域规则速查

### 7.1 文件名解析（对应文档第 3 章）

```text
[字幕组] 番剧名 - 集数 [来源][片源][分辨率][编码 音频][语言][容器].扩展名
```

需提取：`animeRawName`、`episode`、`releaseGroup`、`mediaType`（TV/SP/OVA/OP/ED/NC/MOVIE）、`seasonHint`。

**必测样例**

| 输入 | 期望 |
| --- | --- |
| `[Lilith-Raws] Full Dive - 04 [Baha][WEB-DL][1080p][AVC AAC][CHT][MP4].mp4` | 番剧 `Full Dive`，集数 `04`，字幕组 `Lilith-Raws` |
| `[Lilith-Raws] Full Dive - 03 [Baha][WEB-DL][1080p][AVC AAC]`（文件夹） | 番剧 `Full Dive`，集数 `03`，**与上一条同组** |
| `[喵萌奶茶屋] ぼっち・ざ・ろっく！ - SP01 [1080p].mp4` | mediaType = `SP` |
| `[Group] [Unknown] - 01.mp4` | 无法提取番剧名 → `unrecognized` |

### 7.2 归一化（对应文档 4.1 / 4.7）

```text
预处理 → ① L1 别名表命中 → ② L2 Bangumi 查询（缓存写回别名表） → ③ L3 模糊匹配 → 置信度判定
```

预处理顺序：去 `[...]` 标签 → 去集数段 → 去发布后缀 → 小写 → 全半角统一 → 去分隔符 → 长音符还原 → 繁转简 → 去装饰符号。

### 7.3 归档状态机

| 状态 | 含义 | 是否执行 |
| --- | --- | --- |
| `ready` | 置信度 ≥ 0.90，或人工确认后 | ✅ 执行 |
| `review` | 0.70 ~ 0.90，待人工确认 | ⏸ 确认后才执行 |
| `conflict` | 目标存在同名文件 | ⏸ 用户选择后转为 ready/skipped |
| `deferred` | 用户选「暂不处理」 | ❌ 移入 `_待确认/` |
| `unrecognized` | 置信度 < 0.70 | ❌ 移入 `_未识别/` |
| `skipped` | 用户选「跳过」 | ❌ 不动 |
| `done` | 已移动 | — |

### 7.4 目标路径计算

```text
正常：      {归档根}\{年}\{月两位}\{官方中文名}\{原文件或文件夹}
SP/OVA：    {归档根}\{年}\{月两位}\{官方中文名}\SP\{...}
OP/ED/NC：  {归档根}\{年}\{月两位}\{官方中文名}\OP&ED\{...}
未识别：    {归档根}\_未识别\{原名}\{...}
待确认：    {归档根}\_待确认\{番剧名}\{...}
```

### M2 — 核心引擎（无界面，纯 Node 库 + CLI）

**目标**：输入一个源目录路径，输出一份归档方案 JSON。

**任务**
1. 定义 `types.ts`（照文档第 7 章）
2. `scanner`：递归扫描，过滤视频扩展名，**排除归档根目录**
3. `parser`：文件名 → 番剧名/集数/标签
4. `grouper`：按归一化名 + 字幕组聚类（文件夹与其内文件同组）
5. 内置 `aliases.json`（含文档 4.7.3 的预置条目）
6. `planner`：输出 `ArchivePlan`（entry 含 `fromPath` / `toPath` / `status`）
7. CLI：`npm run plan -- --src "<路径>" --dst "<路径>" --out plan.json`

**自检**
- [ ] 对文档 1.2 的示例目录，`Full Dive - 04` 与文件夹 `Full Dive - 03` **归为同一组**
- [ ] 目标路径为 `...\2021\04\<官方中文名>\`
- [ ] 扫描结果中**不包含**归档根目录里的任何文件
- [ ] 无网络时仍能跑通（走 L1/L3），不崩溃

### M3 — 接入 Bangumi + 模糊匹配

**任务**
1. Bangumi 客户端：`User-Agent`、3 QPS 限流、失败重试、本地缓存
2. 查询结果为唯一 → 写入别名表（`aliases.json`）
3. 模糊匹配（TokenSet + Jaro-Winkler + 编辑距离加权），产出 Top-N 候选
4. 置信度计算 + 阈值分级（0.70 / 0.90）
5. 兜底逻辑：官方中文名 → 通用译名 → 日文原名（**禁用罗马音**）

**自检**
- [ ] `Bocchi the Rock!` / `ぼっち・ざ・ろっく！` 均能命中同一中文名
- [ ] 命中结果被写入 `aliases.json`，**第二次运行不再联网**
- [ ] 断网时降级到 L1/L3，不抛未捕获异常
- [ ] 同名不同作品（如 `Fate` 系列）**不会自动归组**，标记为 `review`

### M4 — 本地服务（文件操作）

**任务**
1. 启动服务：默认 `9999`，占用则 +1 并写回配置；只监听 `127.0.0.1`
2. 接口：`scan` / `plan` / `execute`(SSE 进度) / `revert` / `rename` / `index` / `play` / `shutdown`
3. `executor`：剪切移动；同设备用 `fs.rename`，捕获 `EXDEV` 时降级「复制 → 校验大小 → 删除源」
4. 冲突处理：`(1)` 自动重命名 / 跳过
5. 日志：`logs/batch-<ts>.json`（`originPath` 必存，供撤回）
6. 撤回：整批 + 单文件；原位置有同名 → 加 `(1)`
7. 重命名：**仅番剧文件夹**；校验非法字符、空名、重名
8. `/api/shutdown` 自我退出
9. `bin/start.vbs`（隐藏窗口拉起服务 + 打开浏览器）

**自检**
- [ ] 执行归档后文件确实被移动，且源目录不再有该文件
- [ ] 日志完整记录「原路径 → 新路径」
- [ ] 整批撤销可把本批文件全部移回原位
- [ ] 单文件撤回可只移回一个文件
- [ ] 冲突文件被自动重命名为 `xxx (1).mp4`，旧文件**未被删除**
- [ ] 把归档根目录指向一个不存在的路径 → 中止且**不修改任何源文件**
- [ ] 网页点「⏻ 关闭服务」后进程退出

### M5 — React 界面：视图① 归档整理

## 10. 已知坑（Pitfalls）

| # | 坑 | 处理方式 |
| --- | --- | --- |
| 1 | `fs.rename` 跨设备报 `EXDEV` | 捕获后降级「复制 → 校验 → 删源」 |
| 2 | UNC 路径 + 长路径 > 260 字符 | 拼接 `\\?\UNC\` 前缀；提前预警 |
| 3 | 恶意/异常文件名含 `: ? * " < >` | 生成目录名前做字符白名单清洗 |
| 4 | 扫描时把归档目录自身扫进去 | 绝对路径归一化后判断是否在归档根之内 |
| 5 | Windows 大小写不敏感 | 重名检测时忽略大小写 |
| 6 | Bangumi API 拒绝请求 | 必须带自定义 `User-Agent`；限流 3 QPS |
| 7 | 正则贪婪导致番剧名截断 | `Full Dive RPG` 与 `Full Dive` 需靠 TokenSet 兜住，测试用例要覆盖 |
| 8 | 并发移动过多文件把 NAS 卡死 | ~~串行或并发 ≤ 2，配合进度条~~ ⚠️ **已被 `docs/changes/2026-09-12.md` #1 取代**：实测**有界并发 10** 最优（19.3 s → 6.9 s） |
| 9 | 中文/日文文件名乱码 | 统一 UTF-8；日志与 JSON 用 `utf8` 写出 |
| 10 | 服务关不掉（端口残留） | `shutdown` 后主动 `process.exit`，并在启动时检测端口占用 |
| 11 | 浏览器无法访问 `\\\\NAS\\...` | 所有文件操作**必须**走本地服务，前端只发请求 |
| 12 | 把「改文件夹名」误做成「改文件名」 | 重命名接口只接受「番剧文件夹」目标类型 |

### 10.1 实施期实测补充（含对上方若干条的**修正**）

> 上表是开工前的预判。实际做完 M2–M7 并被用户实测反馈多轮之后，**真正踩到的坑**如下。
> 详细复盘见 `docs/changes/`（按日期归档，索引见 `docs/changes/README.md`），工程细节见 `docs/使用与运维.md` 第 5 章。
> 回编号：**第 8 条「并发 ≤ 2」是错的**（已被 `docs/changes/2026-09-12.md` #1 取代）—— 实测并发 10 才最优（NAS 上 19.3 s → 6.9 s）。

| # | 坑 | 处理方式 |
| --- | --- | --- |
| R1 | 🔴 **UNC 前缀被压掉**（`\\NAS\share` → `\NAS\share`，Windows 当成「当前盘符根」） | 统一用 `joinWinPath()`（先取开头 `\\` 再压中间重复斜杠）；执行前校验目标在归档根内。**真实事故：1076 个文件 / 387 GB 被搬到本机磁盘** |
| R2 | e2e 全用本地临时目录 ⇒ **正好绕过 R1** | 凡「路径拼接 / 越界判定」改动，必须补 **UNC 纯字符串断言** |
| R3 | `windowsHide: true` 会让 `explorer.exe` 窗口**被创建但隐藏**（命令成功、API 返回 ok、屏幕没动静） | 直接 spawn GUI 程序时 `windowsHide: false`；验证手法＝数 `MainWindowTitle`（隐藏窗口不计数） |
| R4 | `explorer /select` 的引号**只能包住路径**（`"/select,path"` 会静默打开「文档」），而 Node `spawn` 默认正好是错的写法 | `windowsVerbatimArguments: true` + 自己拼 `"/select,<path>"` |
| R5 | 🔴 在热路径上调 `aliasKey`/`preprocess`（单次约 40µs） | L3 用**预计算键**（`similarityKeyed`）；新增「按名字遍历」的逻辑前先量 `ms/名字 × 数量`（曾把复核写成 229 ms/名字＝每次扫描多花 172 s） |
| R6 | 每次操作都**整文件重写** JSON（别名表 1MB+/缓存 2MB+） | 常驻内存 + 合并延迟写盘 + 关服务时强制落盘 |
| R7 | 折叠用 `.hidden`（`display:none`）⇒ DOM 照样建（8286 文件行 = 53,782 节点） | 折叠必须**不渲染**（`{!collapsed && …}`），降到 7,809 |
| R8 | 别名表被写入**脏记录**（把「另一季的名字」当成本季的别名，且 `src=manual`、置信度 1.0）⇒ 该季文件永远归错，后续匹配没有纠正机会 | 写时护栏（更长 + 相似度 ≥0.8 拒收）+ 读时「更具体者胜」复核；已归档文件夹也作为证据 |
| R9 | **同名按钮撞车**：卡片头「批量移动＝整部」与新加的「批量移动＝选中项」同名 ⇒ 用户点错，整个文件夹被搬走 | 同一视图内多个「移动」入口，文案必须**自带范围与数量**（整部移动（N）/ 移动整个目录 / 移动选中 N 个） |
| R10 | 长耗时操作**没有反馈**（弹窗点完就关、界面没动静）⇒ 用户以为没生效 → 重复点击 → 重复移动 | 执行期保持弹窗打开 + 进度/秒表 + 禁用按钮 + 全局忙碌遮罩；**失败不清空选择**（可直接重试） |
| R11 | 刷新失败**只写日志**、列表继续显示旧数据 ⇒ 用户以为没生效 → 重复操作 | 失败自动重试一次；仍失败**在界面上显示**（红色提示条 + 重试按钮） |
| R12 | 繁→简字表不全 ⇒ 繁体标题**命中错误条目**（不是搜不到） | 用 OpenCC 完整字表（内嵌数据）；含假名走日文原名，不含假名走简体 |
| R13 | 移动后残留空目录越积越多；但删空目录**绝不能删到归档根** | 向上逐级清理、遇非空/权限失败即停；判定用显式路径比较（`isInside` 含自身，挡不住归档根） |
| R14 | 文件排序按**文件名字符串** ⇒ 多字幕组混排时 01 后面跟 14 | 按**集数数字**排；无集数的（NCOP/特典）排最后。前端渲染与索引用同一套规则 |
| R15 | 要开源/发布时，源码与文档里到处是**真实 NAS 主机名、共享名、盘符、用户名**；`server/data`+`web/data`（含全库文件名）与 `.tools/`（上百 MB）极易被一起推上去 | 先脱敏（统一占位符：`\\NAS\share\…`、`<项目目录>`、`<盘符>:\…`）；`.gitignore` 必须盖住 `data/`、`dist/`、`.tools/`、`node_modules/`；截图只取 `demo/`（模拟数据），**绝不用真机截图**；**自检命令本身也别写真实值** |
